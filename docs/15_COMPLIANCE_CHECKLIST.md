# MVP-23 法務・コンプライアンスチェックリスト

RentPassは、賃貸、個人情報、支払い担保、見守り、オーナー共有を扱うため、通常の業務SaaSよりも法務・コンプライアンス論点が多いプロダクトです。

このドキュメントは、MVPで **自社がやること/やらないこと** を明確にし、専門家確認が必要な項目を切り分けるためのチェックリストです。法的助言ではなく、実装・事業検証前の論点整理として扱います。

## 1. MVPで自社がやること

| 領域 | RentPassがやること |
| --- | --- |
| 申込管理 | 入居希望者の信用パス提出、管理会社レビュー、オーナー向けレポート共有 |
| 条件設計 | 前払い、保証会社、見守り、緊急連絡、保険、残置物対策を条件として組み合わせる |
| 情報整理 | 本人確認・収入・資産・緊急連絡先の確認ステータスを管理する |
| 同意管理 | 管理会社、オーナー、保証会社、保険会社、支援法人への共有同意を管理する |
| 見守り | LINE/SMS/Web等のチェックイン、未応答アラート、対応ログを管理する |
| 外部連携 | eKYC、保証会社、収納代行、信託会社、保険会社のステータスをスタブ/将来APIで管理する |
| 監査ログ | 書類閲覧、レポート共有、状態変更、通知送信をログ化する |

## 2. MVPで自社がやらないこと

| 領域 | やらないこと | 理由 |
| --- | --- | --- |
| 信用審査 | AIで自動的に通す/落とす判断をしない | 差別・説明責任・ブラックボックス化を避ける |
| 信用スコア | 点数で人をランク付けしない | スティグマ化と不透明な審査を避ける |
| 資金預かり | 前払い家賃、敷金、保証金をRentPass口座で保有しない | 資金決済・預り金・資金移動論点を避ける |
| 家賃保証 | RentPass自身が保証会社にならない | 保証業務・与信・回収リスクを避ける |
| 宅建業 | RentPass自身が貸借の代理/媒介を行わない | 宅建業免許論点を避ける |
| 駆けつけ | 自社で訪問・救急・安否確認の現地対応をしない | 事故時責任と運用負荷を避ける |
| 死後事務 | 自社で死後事務や残置物処理を直接受任しない | 法務・実務負荷を避け、専門事業者と連携する |
| 医療情報 | 健康情報や医療情報をMVPの主要データとして扱わない | センシティブ情報を最小化する |

## 3. 個人情報・第三者提供

### 論点

- 本人確認書類、収入証明、資産証明、通帳画像、緊急連絡先、見守り履歴は個人情報性が高い。
- オーナー、保証会社、保険会社、居住支援法人への共有は、目的と項目を明確にして本人同意を取得する。
- 第三者提供に関する確認・記録義務を意識し、誰に何をいつ提供したかを記録する。

### チェックリスト

- [ ] 利用目的を画面と規約で明示する
- [ ] 第三者提供先をカテゴリ別に明示する
- [ ] 共有する情報項目を同意画面で明示する
- [ ] 同意取得日時、同意バージョン、共有先、共有範囲を保存する
- [ ] 同意撤回後の扱いを定義する
- [ ] 書類閲覧時に audit log を残す
- [ ] オーナーには生書類を原則表示しない
- [ ] 保証会社・保険会社・支援法人への共有は目的別同意にする

## 4. 宅建業・広告/媒介該当性

### 論点

- 宅地建物の貸借の代理・媒介を業として行う場合、宅建業免許の論点がある。
- MVPでは一般向け物件検索ポータル、内見予約、仲介申込、成約報酬型の媒介を避ける。
- 管理会社・宅建業者の既存業務に対する業務SaaSとして提供する。

### チェックリスト

- [ ] RentPass上で一般向け物件検索ポータルを提供しない
- [ ] RentPassが貸主/借主の代理として条件交渉しない
- [ ] RentPassが媒介報酬を受け取る形にしない
- [ ] 物件情報は管理会社が登録・管理する
- [ ] 入居者には「紹介された物件/申込中の物件」として表示する
- [ ] 物件広告を行う場合の表示ルールは別途専門家確認する

## 5. 資金決済・預り金・非預託

### 論点

- 入居者から前払い家賃を受け取り、数か月保管し、毎月払い出す設計は重い。
- RentPassは資金を持たず、管理会社、保証会社、収納代行、信託会社のステータスを表示する。
- 外部資金移動/信託/収納スキームの具体化は専門家・外部事業者確認が必要。

### チェックリスト

- [ ] RentPassの利用規約・画面に「RentPassは資金を預からない」と明記する
- [ ] 支払い先を管理会社・保証会社・収納代行・信託会社など外部先として管理する
- [ ] 前払い可能月数と実入金ステータスを分ける
- [ ] 家賃リザーブは外部信託/外部保全先のステータスとして扱う
- [ ] 入居者に未経過分返還条件を説明する導線を設ける
- [ ] オーナーに「支払い対策」として要約表示する
- [ ] 本番連携前に信託会社/収納代行/保証会社とスキーム確認する

---

## 6. 見守り・安否確認

### 論点

- 見守りは「通知を送るだけ」ではなく、未応答時の運用責任が問題になる。
- MVPではRentPass自身が駆けつけや救急判断を直接担わず、管理会社・緊急連絡先・外部支援先の対応ログを支援する。
- 高齢者本人を不安にさせない文言が必要。

### チェックリスト

- [ ] 見守り利用同意を取得する
- [ ] 未応答判定時間を設定できる
- [ ] 本人再通知、緊急連絡先、管理会社、外部支援先の順序を定義する
- [ ] 対応ログに誰が何をしたか残す
- [ ] RentPassが安否・救命を保証しない旨を規約・説明に明記する
- [ ] オーナーには見守り実施状況のみ表示し、健康情報を表示しない

---

## 7. 差別的取扱い・スティグマ回避

### 論点

- 年齢、職業、国籍、保証人有無などを「危険」「低信用」と表現しない。
- RentPassはスコアリングではなく、対策済み項目と受け入れ条件を提示する。

### チェックリスト

- [ ] UIに「信用が低い」「危険」「問題あり」等を出さない
- [ ] 職業名をリスクラベルとして表示しない
- [ ] 「従来審査では信用を証明しにくい人」と表現する
- [ ] オーナー向けレポートは対策済み項目中心にする
- [ ] 自動審査ではなく、管理会社・オーナーの判断補助であることを明記する

---

## 8. 専門家確認が必要な項目

- 利用規約・プライバシーポリシー
- 第三者提供同意の文言
- 保証会社・保険会社・居住支援法人との情報連携契約
- 見守り未応答時の責任範囲
- 前払い・収納代行・信託スキーム
- 残置物処理・死後事務関連の契約導線
- 宅建業/媒介該当性
- 電子契約・重要事項説明連携を行う場合の宅建業者側の責任分界

## 完了条件

- MVPで自社がやること/やらないことが明確になっている。
- 個人情報、宅建業、資金、見守り、スティグマ回避のチェックリストがある。
- 専門家確認が必要な項目が分離されている。
