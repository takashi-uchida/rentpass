# MVP-26 パイロット検証KPI・ヒアリング・導入手順

RentPassは、いきなり大規模SaaSとして販売するより、管理会社・仲介会社・オーナーとの実案件に近いパイロットで、**本当に“貸せる条件”が作れるか** を検証するのが最短です。

このドキュメントでは、初期パイロットの対象、検証KPI、ヒアリング項目、導入手順を整理します。

## パイロットの目的

- 管理会社が審査困難な申込をRentPassに載せたくなるか検証する。
- オーナーが入居安心レポートを見て条件付き承認できるか検証する。
- 高齢者向け見守り、前払い、保証会社、緊急連絡先が承認率に効くか検証する。
- 入居希望者が信用パス作成・書類提出・見守り設定を完了できるか検証する。
- MVP実装前に、手動運用で必要項目と不要項目を見極める。

---

## 1. パイロット対象

### 管理会社・仲介会社

| 条件 | 内容 |
| --- | --- |
| 会社規模 | 地場〜中小規模の賃貸管理会社/仲介会社 |
| 課題 | 高齢者、保証人なし、フリーランス、個人事業主などの審査相談がある |
| 物件 | 空室や受け入れ条件を柔軟に検討できる物件がある |
| オーナー関係 | オーナーと直接コミュニケーションできる |
| 協力度 | 実案件または匿名化ケースで検証に協力できる |

### オーナー

| 条件 | 内容 |
| --- | --- |
| 物件 | 空室または入居条件を見直したい物件がある |
| 課題 | 高齢者・保証人なし・収入証明が難しい人への不安がある |
| 判断 | 入居安心レポートを見て、条件付き承認/追加条件/見送りを判断できる |

### 入居希望者ケース

- 高齢単身者、見守りあり
- 保証人なし、緊急連絡先あり
- フリーランス、前払い可能
- 個人事業主、資産証明あり
- 収入形態が多様で、通常審査では説明しづらい人

## 2. 検証KPI

### 事業KPI

| KPI | 定義 | 目標目安 |
| --- | --- | --- |
| 条件付き承認率 | RentPassで条件設計した申込のうち、条件付き承認された割合 | 30%+ |
| オーナー確認率 | 共有した入居安心レポートが閲覧された割合 | 80%+ |
| オーナー承認率 | レポート閲覧後に承認または条件追加になった割合 | 40%+ |
| 失注回避件数 | 通常なら見送りだった申込を契約検討に戻せた件数 | 月1件以上/社 |
| 空室改善示唆 | 対象物件の空室対策として使えそうか | 定性評価 |

### プロダクトKPI

| KPI | 定義 | 目標目安 |
| --- | --- | --- |
| 信用パス完了率 | 入居希望者が必須項目を完了した割合 | 70%+ |
| 書類提出完了率 | 必要書類が提出された割合 | 70%+ |
| 条件ビルダー完了時間 | 管理会社が条件を作るまでの時間 | 15分以内 |
| レポート作成時間 | 申込詳細からオーナー共有までの時間 | 10分以内 |
| 見守りチェックイン応答率 | 送信した安否確認への応答率 | 80%+ |
| 未応答対応時間 | 未応答から次アクションまでの時間 | 運用基準内 |

### 学習KPI

| KPI | 知りたいこと |
| --- | --- |
| オーナーが最も不安に感じる項目 | 滞納、孤独死、残置物、連絡不能、近隣トラブルのどれか |
| 承認に効いた条件 | 前払い月数、保証会社、見守り頻度、緊急連絡先、保険のどれか |
| 入居者が詰まる箇所 | 書類、前払い、見守り、同意、緊急連絡先のどれか |
| 管理会社の業務負担 | 既存業務に自然に入るか、別オペレーションになるか |
| 有料化ポイント | レポート単価、月額、見守り課金、保証/保険送客のどこか |

## 3. ヒアリング項目

### 管理会社向け

- 審査が難しい申込は月に何件あるか。
- どの属性・ケースでオーナー説明が難しいか。
- 通常はどの段階で見送りになるか。
- オーナーが最も気にするリスクは何か。
- 前払い、保証会社、見守り、緊急連絡先、保険のうち何が承認材料になりそうか。
- 入居安心レポートはオーナー説明に使えるか。
- 条件ビルダーは既存業務に入りそうか。
- 1件あたりいくらなら使うか。
- 月額ならいくらまでなら検討できるか。
- 既存の保証会社・収納代行・見守りサービスは何を使っているか。

### オーナー向け

- 高齢者や保証人なし入居者に対して不安な点は何か。
- 入居安心レポートのどの項目が判断に役立つか。
- どの条件があれば承認を検討できるか。
- 逆に、どの条件があっても難しいケースは何か。
- 通帳画像や詳細書類ではなく、確認済みステータスだけで判断できるか。
- 見守り頻度はどれくらいなら安心材料になるか。
- 前払いは何か月分あれば安心材料になるか。
- 保険や残置物対策の説明は十分か。

### 入居希望者向け

- 申込時に何を証明しづらいと感じたか。
- 前払い条件を提示することに抵抗はあるか。
- どの書類なら提出できるか。
- オーナーにどこまで共有されるか分かりやすいか。
- 見守りチェックインの文面・頻度は受け入れやすいか。
- 緊急連絡先の登録に抵抗はあるか。
- 「信用パス」という表現は受け入れられるか。

## 4. パイロット導入手順

### Step 1: 管理会社候補の選定

- 高齢者入居や保証人なしに課題がある管理会社を探す。
- 既存の保証会社・収納代行・見守りサービスを確認する。
- 管理会社側の担当者と検証範囲を決める。

### Step 2: 対象ケースの選定

- 実案件または匿名化した過去案件を選ぶ。
- 物件、家賃、オーナー不安、入居希望者情報を整理する。
- 個人情報を使う場合は同意と取り扱いを確認する。

### Step 3: 手動で入居安心レポートを作成

- 本人確認、収入・資産、前払い、保証、見守り、緊急連絡先を整理する。
- オーナーには詳細書類ではなく要約情報だけを提示する。
- 推奨受け入れ条件を作る。

### Step 4: オーナー確認

- オーナーに入居安心レポートを見てもらう。
- 承認、条件追加、見送りのどれかを選んでもらう。
- 判断理由をヒアリングする。

### Step 5: 見守りチェックイン検証

- LINE/SMS/Webのどれが使いやすいか確認する。
- 本人応答率、未応答時の対応フロー、緊急連絡先の確認方法を検証する。

### Step 6: 結果レビュー

- 条件付き承認率、処理時間、詰まり箇所を確認する。
- MVP画面に必要な項目/不要な項目を分ける。
- 価格仮説を更新する。

---

## 5. 手動運用で検証する範囲

| 業務 | 手動でよいこと | SaaS化すること |
| --- | --- | --- |
| 書類確認 | 管理会社/運営が目視確認 | 確認ステータス管理 |
| レポート作成 | テンプレートに手入力 | レポート生成画面 |
| オーナー共有 | PDF/URLで手動共有 | 共有URL・閲覧ログ |
| 前払い確認 | 管理会社が入金確認 | ステータス管理 |
| 保証会社連携 | 既存フローで申請 | 申請ステータス管理 |
| 見守り | LINE/SMSで手動/半自動通知 | チェックイン・アラート管理 |

---

## 6. パイロット完了判定

以下を満たせば、MVP実装に進む価値が高いと判断します。

- [ ] 管理会社が「実案件で使いたい」と言う
- [ ] オーナーが入居安心レポートで判断できる
- [ ] 条件付き承認の成功事例が1件以上ある
- [ ] 見守り・前払い・保証のうち、承認に効く条件が見えた
- [ ] 入居希望者が信用パス作成に大きな抵抗を示さない
- [ ] 管理会社が支払う価格仮説がある
- [ ] MVPで作るべき最小画面が確定している

| プラン | 対象 | 価格仮説 |
| --- | --- | --- |
| レポート単発 | 仲介会社/小規模管理会社 | 1件 3,000〜10,000円 |
| 管理会社ライト | 小規模管理会社 | 月額 1〜3万円 |
| 管理会社プロ | 中規模管理会社 | 月額 5〜15万円 |
| 見守り追加 | 入居者単位 | 1人 月額 500〜2,000円 |
| 外部連携 | 保証/保険/見守り/信託 | 成果報酬または月額 |

## 完了条件

- パイロット対象、KPI、ヒアリング項目が定義されている。
- 手動運用で検証する範囲が明確になっている。
- MVP実装へ進む判断基準がある。
