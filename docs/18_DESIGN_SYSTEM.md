# MVP-13 UIコンポーネント/デザインシステム

RentPassのUIは、スコアや危険度で人を分類するのではなく、**確認済み・対策済み・追加確認・条件付き承認** を分かりやすく示すことを優先します。

## デザイン原則

- Stigma-free: 「低信用」「危険」「問題あり」を表示しない。
- Actionable: 不足している項目には次の行動を出す。
- Owner-safe: オーナーには詳細個人情報ではなく、要約と対策済み項目を見せる。
- Senior-friendly: 入居者向け画面は文字を大きく、1画面1タスクを基本にする。
- Auditable: 状態変更や詳細閲覧は監査ログ対象であることを前提にする。

---

## 1. Tone定義

| Tone | 用途 | 例 |
| --- | --- | --- |
| `neutral` | 通常、未開始、不要 | 下書き、利用なし |
| `info` | 進行中、確認中 | 書類確認中、オーナー確認待ち |
| `success` | 完了、対策済み | 本人確認済み、条件付き承認 |
| `warning` | 追加対応が必要 | 追加提出依頼、未応答 |
| `danger` | 緊急対応、見送り | 緊急対応、見送り |

## 3. ステータス表示ルール

### 使ってよい表現

- 確認済み
- 確認中
- 追加確認
- 対策済み
- 条件付き承認
- 見守り設定済み
- 支払い対策あり
- 緊急連絡先確認済み

### 使わない表現

- 低信用
- 危険
- 問題あり
- ブラックリスト
- 夜職リスク
- 高齢者リスク
- 審査突破

---

## 4. 入居安心チェックリスト

`AssuranceChecklist` は、管理会社・オーナー双方で使う中心コンポーネントです。

項目例:

- 本人確認
- 収入確認
- 資産確認
- 前払い条件
- 保証会社
- 見守り
- 緊急連絡先
- 保険
- 残置物対策
- 同意管理

状態:

| Status | 表示 |
| --- | --- |
| `done` | 対策済み |
| `pending` | 確認中 |
| `missing` | 追加確認 |
| `not_required` | 不要 |

---

## 5. オーナー向け表示の原則

`OwnerReportCard` では、以下を守ります。

- 通帳画像や本人確認書類画像を表示しない。
- 健康情報や細かい家族事情を表示しない。
- 「支払い対策」「見守り」「緊急連絡」「保証/保険」の状態を表示する。
- 判断ボタンは「この条件で承認」「条件を追加」「今回は見送り」にする。

---

## 6. 見守りUIの原則

`CheckInCard` は、高齢者でも迷わないようにします。

- 1画面1タスク。
- 主CTAは「元気です」。
- 補助導線は「相談したい」。
- 未応答通知は不安を煽らない。

## 7. 実装メモ

- CSSは既存の `src/styles/globals.css` の `.card` / `.badge` / `.btn` を利用する。
