# RentPass: 要件定義書 (Requirements Specification)

本ドキュメントは、賃貸リスク条件設計プラットフォーム「RentPass」の機能要件および非機能要件を定義します。

---

## 1. システム概要とロール定義

### 1.1 システムロール
| ロール | 説明 | 主な操作 |
| :--- | :--- | :--- |
| **Tenant (入居者・入居希望者)** | 賃貸借契約を希望する個人または現入居者 | 信用パス作成、前払いリザーブ設定、毎日の安否チェックイン、契約状況確認 |
| **Management / Broker (管理会社・仲介会社)** | 賃貸管理会社および客付け仲介事業者 | 案件審査、推奨リスクヘッジ条件設計、安否モニタリング、エスカレーション対応 |
| **Owner (賃貸オーナー)** | 物件の所有者・貸主 | 物件一覧・入居状況確認、リザーブ残高確認、見守り実施状況閲覧 |
| **Admin (RentPass運営管理者)** | プラットフォーム運営者 | 提携信託/保証会社連携管理、居住支援法人連携、監査ログ管理 |

## 2. 機能要件 (Functional Requirements)

### F1. 信用パス（RentPass）作成・条件設計モジュール
- **F1.1 属性・希望条件入力**:
  - 基本情報（氏名、年齢、職業分類: 高齢者/フリーランス/ナイトワーク/その他）
  - 現在の預貯金残高レンジ、希望家賃帯、前払い可能月数（3〜12ヶ月）
  - 緊急連絡先有無、身元引受サービス利用意向
- **F1.2 リスク評価 & 推奨条件生成エンジン**:
  - 属性に応じた懸念項目（滞納懸念、安否懸念、緊急対応懸念）を自動抽出
  - 以下の4要素を組み合わせた「推奨対策パッケージ」を生成
    1. 前払い家賃リザーブプラン（Light / Standard / Premium）
    2. 見守り安否確認頻度（毎日 / 2日に1回 / 週1回）
    3. 残置物処理委任契約の有無
    4. 保証会社・居住支援法人連携プラン
- **F1.3 RentPass PDF / Webサマリー出力**:
  - 管理会社・オーナー提出用の公的提示用サマリーを発行（QRコードによる真正性検証機能付き）

### F2. 見守り・安否確認 & エスカレーションモジュール
- **F2.1 チェックインインターフェース**:
  - LINE Notify / SMS / Web画面からのワンタップ安否報告（「元気です」「要連絡」）
  - スマートメーター / IoT見守りデバイス連携用Webhook受付
- **F2.2 自動リマインド & 段階的エスカレーションフロー**:
  - **レベル0 (正常)**: 定刻までにチェックイン完了
  - **レベル1 (注意 - 12時間未応答)**: 本人へ自動再通知（プッシュ/SMS）
  - **レベル2 (警戒 - 24時間未応答)**: 登録された緊急連絡先への自動通知 & 管理会社アラート
  - **レベル3 (緊急 - 48時間未応答)**: 居住支援法人 / 現地駆けつけ事業者への確認要請発注 & 管理会社・オーナーへの緊急連絡
- **F2.3 アラート管理ダッシュボード**:
  - 未応答者のステータス一覧、対応ステータス（確認中・駆けつけ完了・誤報）更新機能

### F3. 家賃前払い・リザーブ保全連携モジュール
- **F3.1 3段階保全プラン管理**:
  - **Light (簡易)**: 前払い意思証明のみ（資金保全なし、直接オーナー口座等）
  - **Standard (標準)**: 家賃保証会社 + 収納代行連携（月次自動引き落とし・保証付き送金）
  - **Premium (信託保全)**: 外部エスクロー信託会社口座への一括預託。毎月の家賃引き落としと残高保全ステータスをAPI連携
- **F3.2 リザーブ残高 & 払い出しシミュレーション**:
  - 残存月数、毎月払い出し予定額、契約終了時の未経過分返還シミュレータ

### F4. 残置物処理・契約管理モジュール
- **F4.1 電子合意書面生成**:
  - 国土交通省「残置物の処理等に関するモデル契約条項」準拠の電子合意書生成
- **F4.2 受任者・指定人管理**:
  - 死亡時または長期不在時の残置物廃棄受任者（居住支援法人または親族）の登録・承認

## 3. 非機能要件 (Non-Functional Requirements)

| カテゴリ | 要件 |
| :--- | :--- |
| **セキュリティ (Security)** | ・Supabase Row Level Security (RLS) による厳格なテナント分離<br>・機密情報（口座番号・身分証番号等）の暗号化保存<br>・全重要操作の監査ログ（Audit Trail）記録 |
| **可用性 (Availability)** | ・SLA 99.9% 以上のクラウドインフラ（Vercel + Supabase / AWS）<br>・安否確認エンジンの冗長化（SMS/LINE/Email マルチチャネル配信） |
| **法規制準拠 (Compliance)** | ・資金決済法上の「自社非預託」モデル徹底<br>・個人情報保護法（信用情報の目的外利用防止・安全管理措置）<br>・住宅セーフティネット法（居住サポート住宅基準対応） |
| **拡張性 (Scalability)** | ・IoTセンサー（電力・開閉・人感）連携用 REST / Webhook API 設計<br>・外部家賃保証会社 / 信託銀行基幹システムとのバッチ/API連携 |
